# Mraprguild TMDB Telegram Bot

A Render-ready Telegram bot that searches The Movie Database (TMDB) by movie title and returns the movie poster plus detailed movie information. It includes inline search results, pagination, popular/trending/upcoming lists, trailer links, and a button linking to OTTGuild.

**Website configured by default:** `https://ottguild.online/movies/?s={query}`

> This product uses the TMDB API but is not endorsed or certified by TMDB. Movie data and posters are provided by TMDB.

## Features

- Search by typing a movie title or using `/search movie name`.
- `/movie movie name` searches by title; `/movie 27205` loads a TMDB movie ID directly.
- Poster image, synopsis, release date, TMDB rating, genres, runtime, director, writers, cast, languages, countries, production companies, status, budget and revenue (when TMDB provides them).
- Search results with inline buttons and page navigation.
- `/popular`, `/trending`, `/now_playing`, `/top_rated` and `/upcoming`.
- Trailer button when TMDB has a YouTube trailer.
- OTTGuild button using the configurable movie URL template.
- FastAPI health endpoint and secure Telegram webhook for Render.
- Optional local polling runner for testing.
- Secrets are supplied through environment variables; no credentials are hard-coded.


## Docker deployment

The repository includes a `Dockerfile` and `.dockerignore`. Create a local `.env` from `.env.example` and set at least `BOT_TOKEN` and `TMDB_READ_ACCESS_TOKEN`. Keep `.env` private and never commit it.

Build the image:

```bash
docker build -t mraprguild-tmdb-bot .
```

Run the web service (health endpoint: `http://localhost:8000/health`):

```bash
docker run --name mraprguild-tmdb-bot --env-file .env -p 8000:8000 -e PORT=8000 mraprguild-tmdb-bot
```

For Render, create a **Docker** web service from this GitHub repository. Render will detect the `Dockerfile`; add the same environment variables in the Render dashboard. The container starts the FastAPI webhook service using Render's `PORT`.

## 1. Create the Telegram bot

1. Open Telegram and search for **@BotFather**.
2. Send `/newbot` and follow its instructions.
3. Copy the bot token. Keep it private. Do not post it in GitHub or share it publicly.
4. Optional: open the bot's BotFather settings and set a profile photo and description.

## 2. Get TMDB API credentials

1. Sign in or create an account at [themoviedb.org](https://www.themoviedb.org/).
2. Open the account settings and find the API section.
3. Request API access for an application and provide the requested project/contact details.
4. Copy the **API Read Access Token** (the long Bearer token). Use this as `TMDB_READ_ACCESS_TOKEN`.
5. The API v3 key can also be used as `TMDB_API_KEY`, but do not set both unless you know which credential you intend to use.

## 3. Set up the GitHub project

1. Download and extract this ZIP on your computer or phone.
2. Sign in to [GitHub](https://github.com/) and create a new repository, for example `mraprguild-tmdb-telegram-bot`.
3. Upload the files and folders from this extracted project to the repository root. Make sure `render.yaml`, `requirements.txt`, `bot.py`, and the other `.py` files are at the root, not inside an extra nested folder.
4. Do **not** upload a real `.env` file or any bot/API tokens. `.gitignore` already excludes `.env`.

## 4. Deploy on Render

1. Sign in to [Render](https://render.com/) and choose **New + → Blueprint**.
2. Connect the GitHub repository you just created.
3. Render reads `render.yaml` and prepares the web service. Review the settings and create/deploy it.
4. In the service's **Environment** section, add:
   - `BOT_TOKEN` = token from @BotFather
   - `TMDB_READ_ACCESS_TOKEN` = TMDB API Read Access Token
5. Check that `WEBHOOK_SECRET` was generated by the Blueprint. Keep it secret.
6. The application uses Render's `RENDER_EXTERNAL_URL` to register the Telegram webhook automatically. If your deployment platform does not supply that variable, add `WEBHOOK_URL` with the full public HTTPS service URL, for example `https://your-service-name.onrender.com` (no `/telegram/webhook` suffix).
7. Save changes and redeploy if Render asks you to.
8. Open `https://your-service-name.onrender.com/health`. A working service returns JSON with `"status":"ok"`.
9. Open your Telegram bot and send `/start`.

**Important:** Render's available plans, sleep behavior and Blueprint screens can change. Select a plan available in your Render account. A service that sleeps may take a short time to wake before the first message is processed.

## 5. Configure the OTTGuild movie link

The default button is a movie search link:

`https://ottguild.online/movies/?s=Movie%20Name`

This is a safe default based on the movie listing URL you supplied. It assumes the `/movies/` page accepts a WordPress-style `s` search parameter. If your site uses a different URL pattern, change `MOVIE_SITE_URL_TEMPLATE` in Render's Environment settings:

- Search page: `https://ottguild.online/movies/?s={query}`
- Movie slug page: `https://ottguild.online/movies/{slug}/`
- Custom query key: `https://ottguild.online/movies/?movie={query}`

`{query}` is URL-encoded. `{slug}` converts a title into a simple lowercase hyphenated slug. Use the slug option only if your WordPress movie permalinks actually follow that pattern. The bot does not publish movie posts to WordPress; it only makes the link.

| Command | Action |
|---|---|
| `/start` | Welcome and usage information |
| `/help` | Show command list |
| `/search Interstellar` | Search by movie name |
| `/movie Interstellar` | Search by movie name |
| `/movie 27205` | Open details by TMDB ID |
| `/popular` | Popular movies |
| `/trending` | Trending movies this week |

## 7. Optional local test (polling mode)

Use Python 3.11 or later.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env`, fill in `BOT_TOKEN` and `TMDB_READ_ACCESS_TOKEN`, then run:

```bash
python polling.py
```

For local polling, you do not need `WEBHOOK_URL` or `WEBHOOK_SECRET`. Do not run polling and the Render webhook using the same bot token at the same time; Telegram allows only one active update-delivery method per bot.

## Environment variables

| Variable | Required | Purpose |
|---|---:|---|
| `BOT_TOKEN` | Yes | Telegram token from @BotFather |
| `TMDB_READ_ACCESS_TOKEN` | Yes, unless API key used | TMDB Bearer Read Access Token |
| `TMDB_API_KEY` | Alternative | TMDB v3 API key |
| `MOVIE_SITE_URL_TEMPLATE` | No | OTTGuild link template with `{query}` or `{slug}` |
| `WEBHOOK_SECRET` | Recommended | Verifies Telegram webhook requests |
| `WEBHOOK_URL` | Usually auto on Render | Public HTTPS base URL of the deployed service |
| `TMDB_LANGUAGE` | No | TMDB language, default `en-US` |
| `TMDB_IMAGE_SIZE` | No | Poster size, default `w500` |
| `ADMIN_IDS` | No | Comma-separated numeric Telegram user IDs |
| `STATUS_API_KEY` | Recommended for WordPress status | Shared secret for the authenticated `/api/status` endpoint |
| `LOG_LEVEL` | No | Logging level, default `INFO` |

## Troubleshooting

- **Bot does not reply:** check Render service logs, verify `BOT_TOKEN`, and confirm the service is healthy at `/health`.
- **TMDB authentication error:** paste the TMDB *API Read Access Token* into `TMDB_READ_ACCESS_TOKEN`; avoid copying surrounding spaces or quotes.
- **Webhook is not set:** check that the service has a public HTTPS URL. Set `WEBHOOK_URL` to the base URL if `RENDER_EXTERNAL_URL` is not available. Confirm `WEBHOOK_SECRET` contains only letters, numbers, `_` or `-`.
- **OTTGuild button opens the wrong page:** update `MOVIE_SITE_URL_TEMPLATE` to match your site's real search or permalink structure.
- **Poster not displayed:** the details text will still be sent. Check the Render logs and the poster availability in TMDB.
- **Dashboard or static-file error:** make sure the `templates/` and `static/` folders are uploaded alongside `bot.py`; the app uses absolute paths based on the project directory.
- **Movie not found:** try the original English title or a different spelling. TMDB search is not the same as searching your WordPress site's database.

## Security notes

- Never commit `.env`, Telegram tokens, or TMDB credentials to GitHub.
- If a token is exposed, regenerate it with the relevant provider.
- Restrict `/status` using `ADMIN_IDS` if you need the status command.
- The webhook endpoint validates Telegram's secret header when `WEBHOOK_SECRET` is configured.

## 8. WordPress live status connection

The `wordpress-plugin/mraprguild-render-bot-status/` folder contains a companion WordPress plugin. Zip that folder and install it in WordPress, or use the separately supplied WordPress plugin ZIP.

1. In Render Environment, set `STATUS_API_KEY` to a long random secret. The Blueprint can generate this value; copy it securely.
2. Deploy/redeploy the Render service.
3. In WordPress, activate **Mraprguild Render Bot Status** and open **Settings → Mraprguild Bot Status**.
4. Enter the Render base URL (for example `https://your-service.onrender.com`, without `/health`) and the exact same `STATUS_API_KEY`.
5. Add `[mraprguild_bot_status]` to a WordPress page to show live bot status, Telegram connectivity, TMDB configuration and process uptime.

The plugin calls the authenticated `/api/status` endpoint server-to-server. The status API key must never be placed in page HTML or shared publicly. `/health` remains available for Render's health check. Telegram admins can also use `/status` to see configuration and process uptime.

## 9. 24/7 uptime and Render port

The Docker container listens on `0.0.0.0:${PORT:-8000}`. Render supplies `PORT` at runtime; do not set a conflicting port in the WordPress plugin. The `render.yaml` Blueprint uses Docker and a paid always-on `starter` instance setting. Review the plan and pricing shown in your Render account before deploying. Render free web services can spin down after inactivity and are not suitable for guaranteed nonstop bot operation. A paid always-on instance avoids the free-tier idle spin-down, but no hosting provider can guarantee zero interruptions; deploys, crashes and maintenance can still restart a service. Uptime shown is time since the latest process start, not accumulated lifetime.


## Web dashboard template

The Render service root (`/`) serves a responsive Mraprguild control-center page from:
- `templates/index.html`
- `static/css/style.css`
- `static/js/dashboard.js`

The page polls `/api/dashboard-status` every 30 seconds. This endpoint exposes only operational metadata (service state, Telegram connectivity, TMDB credential presence and process uptime); it never returns API keys or the WordPress status secret. The existing authenticated `/api/status` endpoint remains available for the WordPress companion plugin.

### Dashboard endpoints
- `/` — dashboard UI
- `/static/css/style.css` — dashboard styles
- `/static/js/dashboard.js` — dashboard polling and UI updates
- `/api/dashboard-status` — safe public dashboard status
- `/health` — Render health check
- `/api/status` — authenticated WordPress integration status
